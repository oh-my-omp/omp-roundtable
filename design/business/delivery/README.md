# 票据交付与门禁接力

负责单张票据从放上桌面、编写者提交、门禁核验到完成交付的席位接力与门禁失败分流；不负责远端源码漂移对账、跨崩溃未决意图恢复，以及主协调器的唤醒去重。

## 依据

合并前门禁（审查、验收）发现缺陷时编写者仍可在原拉取请求分支上继续提交修复，而合并后门禁或父议题收尾门禁面对的是已合入目标分支的提交，无法靠同一拉取请求原地重提修复（来源：Git 分支与合并不可逆事实）。所以 ``Delivery`GateFailureAction`` 在合并前门禁拒绝时判定为刷新指纹回退返工，在合并后或收尾门禁拒绝时判定为转入升级交主协调器裁定。

## 需求

前置依赖已完成的票据由主协调器放上桌面后，依次经编写者席位交接并留存会话文件、登记并确认外部发布写入、通过必需门禁核验后完成交付（来源：票据交付需求），由 ``Delivery`DeliverTicket`` 走通。

核验门禁给出裁决时，通过则记入门禁通过集合，合并前门禁拒绝则刷新指纹清空已过门禁供编写者返工，合并后或收尾门禁拒绝则将票据升级交主协调器裁定（来源：门禁核验需求），由 ``Delivery`ApplyGateVerdict`` 走通。

席位会话退出时，若未完成交接且修订号仍为当前修订号，则将票据升级交主协调器裁定，不自动重复派发同一修订号（来源：席位异常退出需求），由 ``Delivery`SettleSeatExit`` 走通。
