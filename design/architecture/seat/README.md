# 席位宿主与生命周期

负责管理单次席位会话与检出工作树的生命周期，保证同一票据、角色与修订号至多派发一次，保证同票据下编写者与门禁席位互不并发，并决定新席位是分叉既有编写者会话还是在精确提交上建立干净检出；不负责裁定票据的业务契约。

## 依据

编写者席位在多轮返工中需要保留已建立的代码上下文与推理历史，而审查、验收、合并后核验与父议题收尾门禁若继承编写者会话历史就会丧失独立评判性（来源：系统级需求）。所以 ``Seat`SelectWorkspace`` 对已有交接会话记录的返工 ``<Owner>`` 返回 ``<Fork>`` 复用原工作树并分叉会话，对首次 ``<Owner>`` 与 ``<Closure>`` 返回 ``<Base>``，对其余门禁返回 ``<Commit>`` 检出待评判的精确提交。

席位会话可能因模型异常或工具报错在未调用提交、裁决或升级的情况下结束回合；若宿主对同一修订号无限自动重派，故障席位将陷入死循环（来源：宿主运行约束）。所以 ``Seat`Seats`` 以只增不减的 ``seated`` 集合记录已派发的 ``Seat`SeatSlot``，并在未交接且修订号仍为当前修订号退出时由 ``Seat`Exit`` 返回 ``<Abandon>``。

## 为什么

席位的每版单次派发记录、活动会话互斥与编写者会话文件传承只用到父模块的 ``Ticket`TicketId``、``Ticket`Role`` 与 ``Ticket`Revision``，父模块不需要知道宿主如何创建工作树与原生会话，所以单独成为子模块。

不在席位异常退出时由宿主原地重试同一修订号：只有主协调器能判断未交接退出是由外部环境故障还是契约歧义引起；由 ``Seat`CanSeat`` 禁止同一 ``Seat`SeatSlot`` 二次派发，待主协调器裁定递增 ``Ticket`Revision`` 后才允许派发新槽位。

在 ``Seat`CanSeat`` 中要求 ``<Owner>`` 与同票据所有活动席位互斥、门禁席位与同票据活动 ``<Owner>`` 互斥：返工分叉必须读取前任 ``<Owner>`` 已完整落盘的会话文件并独占该票据的工作树，而门禁席位评判期间也不允许旧 ``<Owner>`` 会话继续活动。

## 语义

`Seat` 运行在协调器进程内，其派发的每个席位是绑定对应工作树目录的无界面原生会话。``<Owner>`` 的工作树在议程存续期间保留供后续返工分叉复用，直至议程收尾时清理；门禁席位（``<Review>``、``<Accept>``、``<PostMerge>``、``<Closure>``）的分离头工作树随该席位退出立即移除（工作树与裸仓库缓存做法见附录 `reference/storage-and-worktrees.md`）。当票据修订号递增使运行中的席位过期时，宿主在该席位下一个工具执行完成边界处中止其会话。
