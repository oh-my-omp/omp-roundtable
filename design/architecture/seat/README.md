# 席位宿主与生命周期

负责管理单次席位会话与检出工作树的生命周期，保证同一票据、角色与修订号至多派发一次，保证同票据下编写者与门禁席位互不并发，并决定新席位是分叉既有编写者会话还是建立干净检出；不负责裁定票据的业务契约。

## 依据

编写者席位在多轮返工中需要保留已建立的代码上下文与推理历史，而核验门禁席位若继承编写者会话历史就会丧失独立评判性（来源：系统级需求）。所以 ``Seat`SelectWorkspace`` 对已有交接会话记录的返工 ``<Owner>`` 返回 ``<Fork>`` 复用原工作树并分叉会话，对其余情形返回 ``<Fresh>`` 在目标提交上建立全新检出与空白会话。

席位会话可能因异常在未完成交接的情况下退出；若宿主对同一修订号自动重派，故障席位将陷入死循环（来源：宿主运行约束）。所以 ``Seat`Seats`` 以只增不减的 ``seated`` 集合记录已派发的 ``Seat`SeatSlot``，并在未交接且修订号仍为当前修订号退出时由 ``Seat`Exit`` 返回 ``<Abandon>``。

## 为什么

席位的每版单次派发记录、活动会话互斥与编写者会话文件传承只用到父模块的 ``Ticket`TicketId``、``Ticket`Gate`` 与 ``Ticket`Revision``，父模块不需要知道宿主如何创建工作树与原生会话，所以单独成为子模块。不在宿主层列举具体的门禁业务名称：将席位角色抽象为 ``<Owner>`` 与绑定 ``Ticket`Gate`` 的 ``Seat`GateSeat``，即可统一表达“编写者独占工作树并传承会话、不同门禁可并行独立检出”。

## 语义

`Seat` 运行在协调器进程内，其派发的每个席位是绑定对应工作树目录的无界面原生会话。``<Owner>`` 的工作树在议程存续期间保留供后续返工分叉复用，直至议程收尾时清理；门禁席位的工作树随该席位退出立即移除（实现参考见附录 `reference/storage-and-worktrees.md`）。
