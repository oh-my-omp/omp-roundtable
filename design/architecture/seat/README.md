# 席位宿主与生命周期

负责分配与结束单次席位会话及检出工作树，保证同一（票据、角色、修订号）槽位至多派发一次，并决定新席位是分叉既有编写者会话还是建立全新检出；不负责裁定票据的业务契约。

## 依据

编写者席位在多轮返工中需要保留已建立的代码上下文与推理历史，而核验门禁席位若继承编写者会话历史就会丧失独立评判性（来源：系统级需求）。所以 ``Seat`SelectWorkspace`` 对已有交接记录的返工 ``<Owner>`` 返回 ``<Fork>`` 复用原工作树并分叉会话，对其余情形返回 ``<Fresh>`` 建立全新检出与空白会话。

席位会话可能因模型或工具异常在未完成交接的情况下结束回合；若宿主对同一修订号无限重派，故障席位将陷入死循环（来源：宿主运行约束）。所以 ``Seat`Seats`` 约束每个 ``Seat`SeatSlot`` 至多对应一个 ``Seat`SeatId``，且在未交接退出时由 ``Seat`Release`` 返回 ``<Abandoned>`` 供上层升级票据。

## 为什么

席位的单次派发记录、活动会话集合与编写者可分叉记录只用到父模块的 ``Ticket`TicketId`` 与 ``Ticket`Revision``，父模块不需要知道宿主如何创建工作树与原生会话，所以单独成为子模块。不让调用方自己管理会话文件句柄：``Seat`Acquire`` 交出 ``Seat`SeatId``，``Seat`Release`` 在编写者完成交接时自动将该票据记入 ``forkable`` 集合。

## 语义

`Seat` 运行在协调器进程内，其派发的每个席位是绑定对应工作树目录的无界面原生会话。``<Owner>`` 的工作树在议程存续期间保留供后续返工分叉复用，直至议程收尾时清理；``<Gate>`` 的工作树随 ``Seat`Release`` 立即移除（实现参考见附录 `reference/storage-and-worktrees.md`）。
