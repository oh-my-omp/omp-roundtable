# 外部写入意图

负责登记对外部系统发起的写入意图，保证同一票据在同一时刻至多有一条在途活动意图，在调用前后记录执行状态并与最新源码事实核对确认，处理进程重启后的未决意图与主协调器的显式处置；不负责定义具体写入动作的业务语义。

## 依据

通过 CLI 或 HTTP 接口向远端发起写操作时，超时、断连或进程中断均不证明远端未生效（来源：GitHub CLI 与 HTTP 接口行为，证据见附录 `evidence/github-write-uncertainty.md`）。所以每次写入前必须先经 ``Effect`BeginExecute`` 持久化为 ``<Executing>``，调用后仅凭最新源码读取经 ``Effect`Confirm`` 确认；未获确认或重启遗留的执行中意图经 ``Effect`Fail`` 或 ``Effect`RecoverExecuting`` 转入 ``<Uncertain>``，交主协调器经 ``Effect`Dispose`` 显式处置。

## 为什么

外部写入意图的持久生命周期只用到父模块的 ``Ticket`TicketId``，父模块不需要知道每次外部调用如何持久记录与恢复，所以单独成为子模块。不把写入动作在架构层展开为具体接口枚举：将动作抽象为 ``Effect`Action``（`token`），使新增或调整远端写入类别时意图表的不变量与连接保持不变。

## 语义

`Effect` 与 `Ticket` 运行在同一协调器进程内，意图表随议程状态在同一原子文件写入中持久化。任何处于 ``<Executing>`` 的意图在进程重启接管时只转为 ``<Uncertain>``，协调器绝不在无人裁定时自动重发该外部请求。
