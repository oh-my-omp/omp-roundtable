# 主协调器唤醒通知

负责从议程当前状态投影出需要主协调器介入的待决决策集合，并在主协调器回合结束或空闲时过滤已通知过的未决事项，只对新出现的派发、升级或收尾决策唤醒主协调器；不负责改变票据或议程状态。

## 依据

主协调器在单个回合内可能连续召集议程、派发多张并行票据或裁定升级，同时后台席位与定时对账也在异步推进；若每次内部状态变化都触发通知或对已知的未决事项重复发消息，主协调器会被冗余回合打断（来源：原生主会话回合调度约束）。所以 ``Attention`OpenDecisions`` 仅投影主协调器能做出的三类决策，``Attention`Observe`` 在主协调器空闲或回合结束时仅返回相较于 ``Attention`NoticeBoard`` 新增的决策。

## 为什么

已通知决策集合与待决决策投影只服务于控制主协调器的唤醒时机，只用到父模块导出的类型与 ``Ticket`Launchable``，父模块的状态流转不需要知道某条决策是否已通知过主协调器，所以单独成为子模块。

不在 ``Attention`Decision`` 中为失败或结果未知的外部写入意图单列第四种分支：外部写入失败或转为结果未知时，所属票据或父议题收尾门禁会递增 ``Ticket`Revision`` 并进入 ``<Escalated>``，从而直接以新的 ``Attention`EscalatedDecision`` 唤醒主协调器；若主协调器在同一回合内自行消解了某条决策（如召集后立即放票上桌），回合结束时该决策已不在 ``Attention`OpenDecisions`` 中，因此静默消退、不再唤醒。

## 语义

`Attention` 运行在协调器进程的内存中，在主协调器处于忙状态时推迟观察，待主协调器当前回合结束或处于空闲时调用一次 ``Attention`Observe``，仅当返回的新增决策集合非空时向主会话发送唤醒消息。
