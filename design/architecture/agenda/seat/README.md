# 席位

负责按账本派发与结束席位、决定席位的工作空间、把在跑席位的交接转进账本，以及席位起不来或没交接时把票据或收口交给 Main；不负责席位内部做什么，也不决定票据怎样前进。

## 为什么

议程不需要知道席位怎样起停，所以席位单独成为子模块；账本是父模块，不能反过来读席位，所以由 ``Seat`` 核对一个交接确实来自绑定这个槽位、仍在跑的席位，再转给 ``Agenda`Produce``、``Agenda`Judge``、``Agenda`JudgeClosure`` 或 ``Agenda`Except``。席位派生的助手没有 ``Seat`Seats.live`` 里的身份，交不了接。

``Seat`Seats`` 只记本进程派发过的槽位，不持久化：进程结束不是席位的失败，被中断的席位在恢复后应当重做一次；恢复需要操作员确认，不会无人值守地反复重做。要跨进程接续的是交接点，它在 ``Agenda`Ticket.point``。

席位以“已交接”结束只看账本是否接受了它的交接（``Seat`Seats.handed``），不由调用方报告：否则一个没交接的席位可以被说成已交接，逃过交给 Main。

评判席位一律空白，产出席位接续交接点（``Seat`Workspace``）：评判继承产出席位的会话就失去独立性，重做的产出席位从零开始就丢掉上一轮的上下文。同一步的几个评判各占一个槽位，可以并行；评判席位只等本票据的产出席位退出。

## 语义

评判席位的工作空间恰是它那一步所看对象的指纹所指的对象，启动前核对。接续的产出席位沿用交接点所指席位的会话与工作空间；那份工作空间保留到议程结束。

``Seat`Dispatch`` 得到 `<Busy>` 时不交给 Main，下一次 ``Relay`Advance`` 再派。

工作期被推进后，没有交接的旧席位在它下一次工具调用结束时停止，不再做旧工作期的事；交接已被接受的席位正常结束。
