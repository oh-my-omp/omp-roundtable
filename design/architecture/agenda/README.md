# 议程账本

负责议程中的票据沿工作流接力、父议题收口、写入意图的登记与确认、退回与例外的原因、交接点与接管；不负责席位怎样起停、唤醒 Main，也不负责工作流与源头判定的具体内容。

## 为什么

用工作期让旧工作作废（``Agenda`Ticket.revision``），不靠锁或撤销：席位与外部子进程发出去就收不回来，迟到的交接只能在交回时按工作期拒收（``Agenda`Handoff`` 的 `<Stale>` 一支）。每次作废在途工作——评判否决、源头否决、交给 Main、Main 裁定、指纹失效——都开启新的工作期。

评判结论记在它那一步所看对象的指纹上（``Agenda`Ticket.passes``），一个评判步骤的几个评判可以并行，写入前要求它依赖的评判都通过于当前指纹：被写入的对象必须正是被评判过的对象。写入确认之后，它依赖的评判就用完了：之后所看对象换了（例如合入之后看合入提交），不作废已经用完的评判，也不会把票据退回已确认的写入之前。

评判进行中指纹变了，只作废评判、回到评判步骤；评判已全部通过、写入尚未确认时指纹变了，交给 Main（``Agenda`Recheck``）：此时被批准的对象已经不是要写入的对象，系统不能自己决定重新评判还是放弃。

交接点（``Agenda`Ticket.point``）放在持久的账本里，不放在只活在进程内的 ``Seat`Seats``：进程重启之后，返工的产出席位仍要接续上一个被接受交接的产出席位。

依赖拓扑由 Main 决定，只在召集与裁定时核对，召集后不随 GitHub 子议题变化自动刷新：拓扑是 Main 的决定，不是 GitHub 的副本。

## 语义

协调器按给定节奏对每张已放行的票据调用一次 ``Relay`Advance``、在有父议题时调用一次 ``Agenda`ReviewClosure``；同一次读取可以用于同一时刻的多张票据。

依赖回退不撤销下游已完成的写入。

收口指纹覆盖 Main 对收口的裁定；``Agenda`ResolveClosure`` 记下的裁定因此让此前的收口评判作废。
