# 议程账本

负责议程中的票据沿工作流接力、父议题收口、写入意图的登记与确认、观察的使用与接管；不负责席位怎样起停、唤醒 Main，也不负责工作流的具体内容。

## 为什么

用工作期让旧工作作废（``Agenda`Ticket.revision``），不靠锁或撤销：席位与外部子进程发出去就收不回来，迟到的交接只能在交回时按工作期拒收（``Agenda`Handoff`` 的 `<Stale>` 一支）。每次作废在途工作——评判否决、交给 Main、Main 裁定、指纹失效——都开启新的工作期。

评判结论记在指纹上（``Agenda`Ticket.approvals``），写入前要求全部评判都通过于观察中的当前指纹：被写入的对象必须正是被评判过的对象。指纹变了只作废评判、回到评判步骤，不必交给 Main。

依赖拓扑由 Main 决定，只在召集与裁定时核对，召集后不随 GitHub 子议题变化自动刷新：拓扑是 Main 的决定，不是 GitHub 的副本。

## 语义

协调器按给定节奏对每张票据调用一次 ``Agenda`Recheck``、在有父议题时调用一次 ``Agenda`ReviewClosure``，并在每次操作中先复核它涉及的票据。

完成后的票据在源头不再满足完成条件时由 ``Agenda`Recheck`` 交回 Main；依赖回退不撤销下游已完成的写入。

收口指纹覆盖 Main 对收口的裁定；``Agenda`ResolveClosure`` 记下的裁定因此让此前的收口评判作废。
