# 议程与票据协调

负责维护议程中的票据依赖有向无环图与票据生命周期状态，保证任何票据仅在其前置依赖全部完成后才能启动或完成，并在升级与裁定时推进票据修订号以废止旧修订号下的工作；不负责外部写入意图的持久对账、席位会话与工作树的宿主管理、主协调器唤醒去重，以及本地链接启动器。

## 依据

同一议程中无依赖关系的票据可并行推进，有依赖关系的票据必须等待前置票据完成交付后才能启动或完成（来源：系统级需求）。所以 ``Ticket`Agenda`` 的不变量规定处于 ``<Active>`` 或 ``<Done>`` 的票据其前置依赖必已全部处于 ``<Done>``，并由纯函数 ``Ticket`DependenciesDone`` 与 ``Ticket`Launchable`` 判定票据何时允许放上桌面。

远端仓库中的议题契约、分支提交或检查状态可能在票据执行期间发生冲突或偏离，席位也可能发现阻塞问题请求主协调器裁定（来源：GitHub 平台行为与系统级需求，证据见附录 `evidence/github-source-drift.md`）。所以 ``Ticket`Escalate`` 将票据转入 ``<Escalated>`` 并递增 ``Ticket`Revision``，主协调器经 ``Ticket`Resolve`` 裁定后交出新的 ``Ticket`Revision``，``Ticket`Complete`` 拒绝任何已被新修订号取代的完成请求。

外部写入在网络超时或进程中断时仍可能已在远端生效（来源：GitHub CLI 与 HTTP 接口行为，证据见附录 `evidence/github-write-uncertainty.md`）。所以持久写入意图与结果未知时的源码找回拆入子模块 `Effect`。

编写者席位需要沿用同一工作树与会话历史做返工，而核验门禁席位必须在干净检出上独立评判且同一修订号只派发一次（来源：系统级需求）。所以席位宿主生命周期拆入子模块 `Seat`。

任何网页都能向本地回环端口发起子资源请求，且终端守护进程在无窗口时仍保持后台运行（来源：浏览器安全策略与 Tern 行为，证据见附录 `evidence/browser-navigation-and-tern.md`）。所以本地点击授权与终端窗口探活拆入子模块 `Launcher`。

## 为什么

票据依赖图与票据状态放在同一个根模块 `Ticket`，因为它们共享“依赖边不出议程票据集、活动或已完成的票据其前置依赖均已完成”这条不变量（``Ticket`Agenda``）。不让调用方自己维护票据修订号：``Ticket`Launch`` 与 ``Ticket`Resolve`` 在准入时交出当前 ``Ticket`Revision``，``Ticket`Complete`` 核对交回的修订号，防止过期席位完成已被升级的票据。

进程崩溃后要求操作员确认原协调器进程已结束才允许接管，而不采用文件锁自动抢占：协调器在途派发的外部 CLI 子进程无法被新进程远程撤销，自动抢占会导致双写。

## 语义

协调器进程由 `--roundtable <owner>/<repo>#<number>` 启动参数唯一标识，在其生命周期内绑定唯一的原生主会话。每次状态变更在返回前原子写入本地状态目录并同步目录项（实现参考见附录 `reference/storage-and-worktrees.md`）。

`Ticket`、`Effect`、`Seat` 与 `Attention` 运行在同一协调器进程内；`Launcher` 运行在独立的本地无状态驻留进程中，与协调器不同存续期。
